# Codex Implementation Task — BLINK MAZE UI & Edge Maze v0.2

## 目的

既存の BLINK MAZE v0.1 を、**「目は床タイルではなく、タイルとタイルの境界にある石壁に埋め込まれている」**方式へ更新する。参考ビジュアルの上品な紙面・植物・不穏な遺跡のトーンは維持。単なるアイコン位置移動でなく、**移動判定も境界式へ改修**する。

### 着手前
1. リポジトリを調べて現状のUI、ロジック、テスト、画像・著作権/出典管理方式を把握する。既存の保存・JA/EN・効果音・スマホ対応がある場合は維持。
2. 参考：`BLINK_MAZE_UI_ROUGH_v0.2.md`、`BLINK_MAZE_EDGE_LEVELS_v0.2.json`。リポジトリに取り込むときにパスは合わせてよい。
3. `BLINK_MAZE_DESIGN_v0.1.md` と旧 `BLINK_MAZE_LEVELS_v0.1.json` は旧**タイル型**。**旧盤面をそのまま新ゲームに流用禁止**。更新後の遊び方・ソルバー・QAを同時に入れ替える。
4. リポジトリが空の場合は依存最小のVite+TypeScript/HTML+CSS。既存環境がある場合は新規フレームワークを増やさない。

## P0 — ロジックの入れ替え

### 新しいデータモデル

タイルは `width × height` の床セル。壁は**隣接2セル間のedge**。

```ts
type Phase = 0 | 1;
type EdgeKind = 'stone' | 'open' | 'A' | 'B';
type Direction = 'R' | 'D';
type Connection = { x: number; y: number; dir: Direction; kind: Exclude<EdgeKind, 'stone'> };
type LevelV2 = {
  id: string; title: string; width: number; height: number;
  start: [number, number]; goal: [number, number];
  blinkLimit: number; initialPhase: Phase;
  connections: Connection[];
};
```

- `connections` に**記述されていないすべての隣接境界は固定の石壁**。盤面外周も常に固定壁。
- edge `{x,y,dir:'R'}` は床 `(x,y)` と `(x+1,y)` の間、`dir:'D'` は `(x,y)` と `(x,y+1)` の間。
- 同一の境界の重複定義、範囲外、start/goal不正、blinkLimit負数はエラー。
- `A`は青い目、`B`は琥珀の目。位相0はA開/B閉。位相1はA閉/B開。

```ts
function blocks(kind: EdgeKind, phase: Phase): boolean {
  if (kind === 'stone') return true;
  if (kind === 'open') return false;
  return kind === 'A' ? phase === 0 : phase === 1;
}
```

### 移動とBLINK

- 移動キーを押したら現在座標と行き先座標の間の正規化edgeを調べ、`blocks` が偽なら移動。左右上下の逆方向を正しく同じedgeへ正規化する。
- `BLINK` は全体位相を反転し `blinksUsed++`。残り0なら拒否、予算消費なし。BLINKは位置に依存しない。
- **旧ルールの「目の上にいるとBLINK禁止」「BLINKでプレイヤーが壁に埋まる」処理を削除**。プレイヤーは床セル中央におり、セル自体の通行可否は変化しない。
- UNDOは移動または成功したBLINKの状態スナップショットを戻す。失敗操作は履歴に積まない。
- RESTARTはlevel.initialPhaseと予算を含め初期化。goal到達でクリア。進行保存は旧式を壊さないようid/versionを確認。

## P1 — レンダリング

### 優先案：SVGレイヤー＋HTML UI

- 盤面は各セル同寸のSVG viewBoxまたはタイルGrid＋壁SVGオーバーレイで描画する。
- セル中心を `(x+0.5, y+0.5)` とみなす。境界線は整数格子位置、**目付き石壁は境界線分の中央**に置く。
- レイヤー：床 → 固定石壁 → 目付き可動壁/開口 → プレイヤーと出口 → エフェクト。
- `stone` は太い苔色線分/石の板。`open` は線分を描かない。
- `A/B` の**開眼中**は固定壁と同じ厚さの石板を描き、中央に丸/菱形の虹彩。**閉眼中**は横・縦の石板を左右／上下に引いて開口を作り、閉眼のエンブレムを薄く残す。視覚上開いているかと当たり判定は必ず一致。
- 壁の向きは縦/横対応。床タイル中央へ眼アイコンを置く実装は禁止。
- 絵の生成だけで迷路を構成しない。画像は世界観/テクスチャ、遊べる境界はコードで描画。

### デスクトップ

- 参考モック：上部 BLINK MAZE、左の絵本的な廃墟/眼のキービジュアル、右のステージ名/予算/盤面/凡例/操作。
- タイポグラフィは上品な見出し＋読みやすい操作書体。深緑、オフホワイト、青、琥珀。
- 目標幅は 1280〜1700px。ただし固定幅にしない。

### スマホ（重要）

- 360×800 / 720×1280でゲームの説明・盤面・BLINK・方向キーをスクロールなしで扱える。
- 左の大きなイラストは非表示かヘッダーに縮小。盤面横幅 `min(100%, availableWidth)`、縦横比維持。
- BLINKボタンと方向キーは44px以上のタップ領域。Undo、Restartも手が届く位置。
- タップやキー連打で意図しないスクロール/ブラウザ操作が起きないようにする。
- クリア時 NEXT/REPLAY、レベル選択/保存とJA/EN表示も維持。

## P2 — 目の演出（後回しにできる）

- 150〜220msのまばたき：瞼閉じる → 石壁がすべる → 別グループが開眼。
- 状態更新は原子的に行い、表示アニメの途中で通行判定がズレないよう入力を短時間ロック。
- `prefers-reduced-motion` では即時切替。
- 効果音は薄い「ぱちっ」「こつん」。ミュートは常時可能。無音でも完全に理解可能。

## 新ステージの採用

`BLINK_MAZE_EDGE_LEVELS_v0.2.json` の全5問を使う（v0.1の8問は変換しない）。以下はPythonのBFSで検証済みの解法（`T`=BLINK）：

| ID | 名称 | 予算 | BFS検証済み操作列 | 合計操作 |
|---|---|---:|---|---:|
| 001 | FIRST BLINK | 1 | `RTRR` | 4 |
| 002 | TWO KINDS OF EYES | 2 | `RTRRTR` | 6 |
| 003 | ALREADY ASLEEP | 1 | `RRTRR` | 5 |
| 004 | THE LONG WAY AROUND | 1 | `RDRRUTR` | 7 |
| 005 | FEWER BLINKS, LONGER WALK | 1 | `RDRRRTRUR` | 9 |

操作列は上記のJSONとともに変更時に再検証。初期位相0。最短解の一例だが、一意解や体感難易度は未検証。

## P3 — テスト/QA（合格条件）

1. 各JSONの `verifiedSolution` をレベルごとに適用するとgoal到達。全5面BFSで解ける。
2. 現位相で閉眼の目付き壁を通れるが、開眼の目付き壁には阻まれる。A/Bが逆位相で変わる。
3. 足元がどの床でも、予算が残る限りBLINK可能。床セルは消えない。
4. 壁は全て**マスの境界**に描画され、目が床中央に浮かない。縦壁と横壁を含めて確認。
5. 盤面外への移動不可。未定義edgeは壁。UNDOでphase/予算/位置が戻る。
6. 残り0でBLINK拒否、失敗操作は予算を消費せずUndoにも積まない。
7. 360×800 / 720×1280 / デスクトップのスクリーンショットで盤面・操作の重なりや欠けなし。特にスマホで横スクロールなし。
8. 英語/日本語の説明は『目のある壁』で統一し、旧『目のあるマスに立つ』表現を全撤去。
9. リグレッション：レベル選択、保存、BGMミュート、キーボード/タッチ操作、クリア遷移が壊れていない。
10. ゲーム本編で勝手にレベル生成・ルールの追加を行わない。
