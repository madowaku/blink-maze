# BLINK MAZE 詳細設計・Codex実装仕様 v0.1

対象：Trijam #393 / The Walls Have Eyes。目標：3時間以内に完走できるブラウザ向けターン制グリッドパズル。

## 企画の核

- キャッチコピー：**目を閉じれば、道が開く。でも、別の目が覚めてしまう。**
- 青い目 `A` と琥珀の目 `B` は常に反対の開閉状態。初期状態は A=開・B=閉。
- **開いた目は壁**、**閉じた目は歩ける床**。全マップ一斉に反転するBLINKで切り替える。
- 目の上に立ったまま、その目が開くようなBLINKは禁止。プレイヤーは壁に埋まらない。
- **各ステージにはBLINK予算（回数上限）がある**。この制約がないと最寄りの安全床で毎回切り替えるだけになり、経路の選択が浅くなるため採用した。移動手数は無制限。
- いつでもUNDO/RESTARTできる。ミスは即取り消せる。タイミング操作・死亡・敵・時間切れなし。

## ターゲット体験

(1) 閉じた目を通る → (2) 開いた目に阻まれる → (3) 切り替える位置を考える → (4) 直接の近道より少ないBLINKで済む迂回路を発見する。

## 入力・UI

- 矢印キー/WASD/画面方向ボタン：上下左右1マス移動。
- Space / `BLINK`ボタン：世界を反転。0回残り・安全違反なら反転不可、消費なし。
- Z / `UNDO`：直前の成功した移動／BLINKを1手戻す。残り予算も復元。
- R / `RESTART`：レベル開始時に戻す。
- 画面上部：レベル番号・短いレベル名・残りBLINK数。中央：盤面。下：大きい BLINK + UNDO + RESTART と方向キー。
- 360×800に収まる優先順位：盤面サイズ（最大11列×7行） → 主要ボタン → 短いヒント。レイアウトは縦画面を主にPCにも対応。
- 最初のヘルプ文：『開いた目は壁。閉じた目は道。BLINKで入れ替えよう。』
- 第002面の補助：『目の上にいると、開くことはできない。』
- 第005面の補助（任意ヒント）：『近い道が、少ないまばたきとは限らない。』
- 色覚差への配慮：青い目 A は丸い瞳、琥珀 B は菱形の瞳や異なるまつ毛。開眼／閉眼は形と通行表示でも判別可能に。

## 状態と挙動

```ts
type Phase = 0 | 1; // 0: A open, B closed; 1: A closed, B open
type GameState = {
  levelId: string;
  x: number;
  y: number;
  phase: Phase;
  blinksUsed: number;
  undoStack: Snapshot[];
  completed: boolean;
};

function isBlocked(tile: string, phase: Phase): boolean {
  return tile === '#' || (tile === 'A' && phase === 0) || (tile === 'B' && phase === 1);
}

function tryMove(dx: number, dy: number): void {
  // 境界内かつ次のマスが非壁ならスナップショットを保存して移動。
  // 移動先がGならクリア。失敗入力はUndo履歴に残さない。
}

function tryBlink(): void {
  if (state.blinksUsed >= level.blinkLimit) return;
  const nextPhase = (1 - state.phase) as Phase;
  // 現在座標が次のPhaseで壁になる場合、禁止。回数は消費しない。
  if (isBlocked(tileAt(state.x, state.y), nextPhase)) return;
  pushUndoSnapshot();
  state.phase = nextPhase;
  state.blinksUsed++;
}
```

- ステージ初期化時：Phase=0、blinksUsed=0。各ステージで世界状態もリセット。
- `A/B` はタイル座標であり、プレイヤーの下に閉じた目を描画できるよう床・目・キャラクターを分離。
- T=BLINK成功。失敗入力・アニメ中の入力は世界状態を変えない。
- クリア後は入力を停止、NEXT/REPLAY/LEVEL SELECTを表示。進行はlocalStorageへ保存、未対応環境ならセッション内のみで継続可能。
- 絵・音は演出だけでありゲーム判定と同期タイミング依存しない。1回のBLINK演出は約150ms。UI可読性を優先。

## レベル記法・検証

`#` 固定壁、`.` 通常床、`S` 開始位置、`G` 出口、`A` 青い目、`B` 琥珀の目。
全ステージPhase=0でスタート。`R/L/U/D`=移動、`T`=BLINK。最短解は『1操作＝1』としてBFSで確認したもので、最短BLINK優先の最短手順とは限らない。レベルの解が少なくとも1つ存在することと、指定BLINK制限でクリアできることを自動検証済み。


## ステージ設計（全8問）

### Stage 001：はじめてのまばたき
ねらい：目を閉じると壁を通り抜けられる。上限1回、検証済み5操作（うちBLINK 1回）。
```text
#######
#S.A.G#
#######
```
検証用手順：`RTRRR`

### Stage 002：安全な足場
ねらい：閉じた目の上では世界を切り替えられない。上限2回、検証済み8操作（うちBLINK 2回）。
```text
#########
#S.A.B.G#
#########
```
検証用手順：`RTRRTRRR`

### Stage 003：眠っている目
ねらい：最初にまばたきしない方がよい場合がある。上限1回、検証済み9操作（うちBLINK 1回）。
```text
#########
#S.B#...#
###.###.#
#...A..G#
#########
```
検証用手順：`RRDDTRRRR`

### Stage 004：目と目のすきま
ねらい：異色の目が直結している場所は通れない。安全床を経由する。上限2回、検証済み12操作（うちBLINK 2回）。
```text
#########
#S..AB.G#
#..##...#
#..A.B..#
#########
```
検証用手順：`RDDTRRTRRRUU`

### Stage 005：遠回りこそ近道
ねらい：直線の近道は２まばたき必要だが、迂回路なら１回でよい。上限1回、検証済み13操作（うちBLINK 1回）。
```text
###########
#S..A.B..G#
#.#######.#
#..B.A....#
###########
```
検証用手順：`DDRRRTRRRRRUU`

### Stage 006：ジグザグまばたき
ねらい：通路とまばたきの順序を長い迷路に応用する。上限3回、検証済み19操作（うちBLINK 3回）。
```text
#######
#S.A..#
#####.#
#..B..#
#.#####
#..A.G#
#######
```
検証用手順：`RTRRRDDLTLLLDDRTRRR`

### Stage 007：まばたき禁止
ねらい：切り替えないという選択にも価値がある。上限0回、検証済み12操作（うちBLINK 0回）。
```text
###########
#S..A....G#
#.#######.#
#..B......#
###########
```
検証用手順：`DDRRRRRRRRUU`

### Stage 008：最後の選択
ねらい：見かけ上の近道より少ない切り替えで済む経路を選ぶ。上限2回、検証済み14操作（うちBLINK 2回）。

###########

3. 01:00〜01:35 001〜005のレベル読込とクリア遷移、Undo/Restart。
4. 01:35〜02:05 目の開閉・壁変化の150ms演出、SE、ゲームロゴ。

### 推奨技術

依存ゼロのHTML / CSS Grid / JavaScript。タイルはHTML要素で描画する（最大77タイル）、状態ロジックは描画と分離する。既存Viteテンプレートがある場合はVite+TypeScriptでも可。重いゲームエンジンやアニメライブラリは不要。

### 最低限のQA

- 全8レベルでJSON付属の `verifiedSolution` を再生してゴール到達する。
- 予算超過時に切り替わらず、UNDOで消費済みBLINKが戻る。
- 閉じた目の上で、その目を開くBLINKは拒否される。拒否操作は予算消費なし。
- 壁・マップ外への移動拒否。最終BLINKを使ってもUNDO/RESTARTが動作する。
- 各レベル初期化でPhase=0へ復帰、S/G座標の妥当性、レベルの行長が均一。
- タッチ操作で意図せぬスクロール・連続長押し暴走・画面外UIがない。
- 動画/GIF演出がなくても、テキストとアイコンだけでルール理解可能。

### 設計上の注意・改修余地

- 最も重要なリスクは『実際には目の切り替えではなく単なる迂回迷路になっている』こと。Stage005での気づき、Stage004での隣接異色眼の理解を観察して判断する。
- Stage007の0回は意図的な休憩問題。評価が悪ければ短い変奏へ差替える。
- MVPでは『目の開閉による床の存在/非存在』は採用しない。消滅した床とプレイヤーの扱いが難しく、物理や落下・死亡の処理が増えるため。
- 投稿後のv0.2候補：2色以外のルールを追加する前に『目を閉じるのは壁を通るためだけでなく、経路を最適化するため』のレベルを増やす。
